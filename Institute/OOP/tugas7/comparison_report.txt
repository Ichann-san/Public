EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
This report provides a detailed comparison between two implementations of a 
big integer class using the Karatsuba multiplication algorithm. The first 
implementation (karatsuba.cpp) prioritizes readability and educational value, 
while the second (part7.cpp) focuses on performance optimization for 
competitive programming scenarios.


1. CODE STRUCTURE & NAMING CONVENTIONS
--------------------------------------------------------------------------------

karatsuba.cpp:
- Uses Indonesian naming conventions (hapus0, pengali)
- Template-based input function: getnum<T>()
- Modular design with separate solve() function
- More verbose and descriptive

part7.cpp:
- Uses English naming conventions (trim, other)

- More compact and integrated


2. DIGIT STORAGE SYSTEM (CRITICAL DIFFERENCE)
--------------------------------------------------------------------------------

karatsuba.cpp - Base-10 Representation:
- Each vector element stores ONE decimal digit (0-9)
- Example: digits = {5, 3, 2} represents 235
- Memory usage: 32 bits per decimal digit
- Advantage: Simple to understand and debug
- Disadvantage: Inefficient memory usage and more operations

part7.cpp - Base-100,000,000 Representation:
- Each vector element stores EIGHT decimal digits (0-99,999,999)
- Example: a = {12345678, 987} represents 98712345678
- Memory usage: 4 bits per decimal digit (8× more efficient)
- Advantage: Fewer operations, better cache performance
- Disadvantage: More complex carry handling


3. KARATSUBA ALGORITHM IMPLEMENTATION
--------------------------------------------------------------------------------

karatsuba.cpp Implementation:
- Method: Private function karatsuba(const ll& a, const ll& b)
- Splits numbers at digit position m
- Uses helper functions: addLL(), subtractLL(), shiftLeft()
- Creates new objects for each operation (functional approach)
- Cutoff threshold: 32 decimal digits
- More readable and educational

part7.cpp Implementation:
- Method: Overloaded operator*(const ll& other)
- Splits numbers at array index k (each index = 8 digits)
- Uses add_internal(shift) for efficient shifted operations
- Modifies objects in-place (imperative approach)
- Cutoff threshold: 32 array elements = 256 decimal digits
- More optimized for performance

Karatsuba Algorithm Steps (Both):
1. Split numbers: x = x1*B^k + x0, y = y1*B^k + y0
2. Compute three products:
   - z0 = x0 * y0
   - z2 = x1 * y1
   - z1 = (x0+x1) * (y0+y1) - z0 - z2
3. Combine: result = z2*B^(2k) + z1*B^k + z0
4. Time complexity: O(n^1.585) vs O(n²) for standard multiplication


4. ARITHMETIC OPERATIONS COMPARISON
--------------------------------------------------------------------------------

Addition:
- karatsuba.cpp: addLL(a, b) - creates new object
- part7.cpp: add_internal(other, shift) - modifies in-place

Subtraction:
- karatsuba.cpp: subtractLL(a, b) - creates new object
- part7.cpp: sub_internal(other, shift) - modifies in-place

Shift Operation:
- karatsuba.cpp: shiftLeft(n) - inserts n zeros at beginning
- part7.cpp: Uses shift parameter in add/sub operations

Carry Handling:
- karatsuba.cpp: Simple (max carry = 9 in base-10)
- part7.cpp: Complex (large numbers in base-10^8)


5. MULTIPLICATION FALLBACK MECHANISM
--------------------------------------------------------------------------------

karatsuba.cpp:
- Condition: if (n <= 32)
- Meaning: 32 decimal digits
- Fallback: gradeSchoolMultiply() - nested loops with base-10 carries

part7.cpp:
- Condition: if (n <= KARATSUBA_CUTOFF) where KARATSUBA_CUTOFF = 32
- Meaning: 32 array elements = 256 decimal digits
- Fallback: multiply_base() - nested loops with base-10^8 carries

Reason for Fallback:
Karatsuba's divide-and-conquer overhead exceeds its benefits for small 
inputs. The recursive function calls and object allocations become more 
expensive than simple nested loops for small numbers.

part7.cpp provides:
